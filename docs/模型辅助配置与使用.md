# 模型辅助配置与使用

提供两项功能：玩家在结算发布后生成速览，主持人在结算草稿中根据已定裁定起草反馈。没有策略建议、行动预测或自动裁决。

## 网页全局配置（推荐）

系统管理员登录后，点击页面顶部的 **全局 AI 设置**，填写调用地址、API Key 和模型名称，勾选“启用全站 AI 服务”并保存。立即对所有游戏和玩家生效，无需逐局开启、填写个人密钥或重启 API。普通玩家和单局主持人均不能读取或修改全局设置。

调用地址可填写基础地址（如 `https://example.com/v1`），也可填写完整的 `/chat/completions` 地址，保存时会规范化。只接受 HTTP/HTTPS，不接受地址中的用户名、密码、查询参数或片段；可以使用自己的局域网兼容服务。服务类型选择 OpenAI 兼容、DeepSeek 或 GLM，模型标识按服务商控制台填写。

保存后可点击“测试已保存的连接”，验证鉴权、模型调用和结构化输出。测试仅发送固定测试文字，不发送游戏资料，也不会自动调用。兼容端点不支持 `response_format` 时，可在兼容选项中关闭 JSON 输出模式；返回内容仍需通过 JSON 结构和来源校验。

已保存的 API Key 不回显，只显示是否已配置。只修改模型名称等参数时，密钥留空可保留；更换地址或提供商时须重新填写，避免将旧服务密钥发送到另一地址。多人同时编辑会通过版本号拒绝过时保存。全局停用会停止所有游戏的 AI 调用，不会改用环境变量里的另一套密钥。

密钥以 AES-256-GCM 加密后存入数据库。加密密钥自动生成在备份数据卷的 `.private/assistant.key`，不需要另配环境变量；正常镜像更新、重建容器和服务器重启均保留。迁移到新 NAS 或恢复备份时也应保留该文件；只恢复数据库而丢失加密文件时，管理员可重新填写 API Key，游戏存档不受影响。实际密钥、加密文件和输入框内容不会写入前端本地草稿或公开镜像。

新安装的第一位初始化主持人具有系统管理员身份。旧安装若完全没有系统管理员，迁移仅为最早创建且仍有效的初始化账号补齐身份；已有管理员或最早账号已停用时不会另行授权其他账号。更新后刷新页面读取新身份。

## 服务器环境变量（兼容方式）

在项目根目录的私有 `.env` 中配置，随后重启 API。变量不能使用 `VITE_` 前缀。密钥不会发往游戏浏览器，也不要把密钥贴在聊天、规则或政策里。

DeepSeek 示例：

```dotenv
LLM_PROVIDER=deepseek
LLM_API_KEY=填入自己的API密钥
LLM_MODEL=deepseek-flash
```

GLM 示例（选择自己账号实际可调用的文本模型）：

```dotenv
LLM_PROVIDER=glm
LLM_API_KEY=填入自己的API密钥
LLM_MODEL=glm-4.7-flash
```

服务基础地址默认分别为 `https://api.deepseek.com` 和 `https://open.bigmodel.cn/api/paas/v4`，程序在其后追加 `/chat/completions`。如账号使用其他专用端点，维护者可显式填写 `LLM_BASE_URL`。切换提供商时，记得同时更新密钥、模型名称，以及此前显式设置过的基础地址。

其他兼容服务使用 `LLM_PROVIDER=compatible`，且必须填写 `LLM_BASE_URL`。不接受基础地址中的用户名、密码、查询参数或片段。尚未保存网页全局配置时，仍可沿用此方式和原来的逐局开关；保存全局配置后，以全局配置为准。

默认请求 JSON 输出，DeepSeek / GLM 默认发送 `thinking: { type: 'disabled' }`。若选用的旧模型不支持该字段，设置 `LLM_DISABLE_THINKING=false`；兼容服务始终不发送供应商专有字段。只支持普通文本的兼容端点可设置 `LLM_JSON_MODE=false`，程序仍会要求并校验 JSON，不会把未经校验的自由文本当作成功结果。

接口依据：[DeepSeek 对话补全文档](https://api-docs.deepseek.com/api/create-chat-completion/)、[智谱对话补全文档](https://docs.bigmodel.cn/api-reference/模型-api/对话补全)。这些示例不代表模型定价或账户可用性，模型名称以服务商控制台为准。

本地开发使用项目原有的 API 启动命令。Compose 部署时，需将这些变量注入 `api.environment`；运行 Compose 的 shell 或 `--env-file` 负责提供值。不要只修改宿主机 `.env` 而未传入容器。没有密钥或模型名称时，辅助功能保持关闭，游戏的常规流程仍可使用。

## 开启与操作

1. 管理员保存并启用全局配置后，所有游戏自动共用。“剧本与规则 → 模型辅助设置”显示全局服务状态。仅沿用环境变量时，仍需主持人开启本局辅助。
2. 结算发布后，成员在“回合结果 → 结算速览”选择篇幅，再点击生成。主持人看到自己的完整结算范围，玩家看到本国反馈与公共公告，旁观者只看到公共内容。
3. 主持人在“回合结算”选中政策，先保存变更计划，再打开“起草反馈”，填写已决定的结果。生成的正文只有点击“填入反馈”才进入编辑栏，仍须按原流程保存和发布。

篇幅为软目标：简短约 120～250 字，适中约 300～600 字，详细约 600～1000 字。不凑字，也不按目标强行截断；另外设置较宽的字段和总长度上限，避免异常长回复。

速览采用“一句话概括 + 结果要点 + 必要的资料说明”。可展开原文核对。收支表使用该回合已入账的结算与更正记录汇总，由程序计算；不包含开局余额设置，也不把当前余额当成历史余额。模型不得把政策意图、传闻、未发布计划或未记录的数据说成确定结果。

历史结算后来发生的资源或兵力更正也会进入摘要资料，并保留执行时间。资源更正按实际执行回合入账，不会倒改历史回合的收支总额，也不会把更正通知与对应账目累计两次。

模型可能概括失真，来源引用校验不能证明文字绝对正确。原结算记录仍是依据；本功能不修改正式记录。主持人遇到裁定与计划冲突时，应先核对原资料。模型生成的反馈只有经主持人采用、保存并发布后才成为游戏反馈。

输出按“实际结果、代价与损失、尚未完成与待确认、更正记录”分组，每项带简短标题和可展开的原文依据。模型收到游戏、回合、读者身份与程序核算的收支净变化，有助于避免混淆时间、对象和重复计数。反馈起草按整份回合政策的分类条逐项回应已裁定事项；分类不成为行动限制。可直接复制速览或反馈草稿，复制不会保存或发布结算。

## 权限与运行边界

- 服务端先执行现有结算可见性过滤，再组装模型资料。速览不发送其他国家私密政策、未提交草稿、聊天记录、完整地图或军队真值。探索记录保留传闻、过时等标记。
- 玩家不能上传自定义系统提示词、模型地址、上下文或伪造裁定；反馈起草只允许活动局的主持人在当前结算阶段调用。
- 生成前后核对成员身份、国家归属、结算版本、更正记录及相关内容；变化后丢弃结果。返回前再次核对登录会话。编辑框期间有改动时，禁止覆盖新文字。
- 模型没有工具或数据写入能力。不自动提交政策、扣除资源、修改地图、掷骰、保存或发布结算。
- 默认等待上限 60 秒，可配置 `LLM_TIMEOUT_MS` 为 1000～120000。输出截断、格式错误、未知来源 ID 和外部服务错误都会显示失败；不会静默重试，也不会自动切换服务商。
- 每用户每小时最多 30 次、每局每 24 小时最多 300 次通过校验的生成尝试；计数保存在数据库，外部调用失败也会计数，以防故障反复消耗。拒绝次数仍会累计但不会延长窗口。
- 当前单 API 进程同时最多 3 次、每用户同时 1 次。多进程部署前需改为共享并发控制；持久配额已跨进程共享。
- 结果仅保留在当前页面内存，不写入结算、数据库摘要表或聊天记录；刷新或服务重启后不保证保留。关闭面板保留其本次结果，不会自动生成。模型服务商会接收本次相关文字，其数据处理遵循你选择的服务条款。
- API 不记录提示词、生成正文或上游原始错误，日志遮蔽 API 密钥。配额记录仅含哈希桶、次数和过期时间；全局配置使用迁移 029 中的独立单行设置表，不向玩家返回地址、密钥或加密内容。

## 验证范围

自动化覆盖供应商请求格式、输出结构与长度、来源校验、权限过滤、正式账目汇总、过时版本、生成中权限变化、登录撤销、重复点击、失败不重试及手动填入反馈。

当前未配置真实 API 密钥，尚未验证 DeepSeek / GLM 的实际输出质量和账号可用性。接口模拟测试不能替代真实模型试用；接入后应用同一组真实结算样本检查：失败是否保留、数字是否一致、有无擅自添加建议、是否遗漏关键代价和是否混淆传闻。
