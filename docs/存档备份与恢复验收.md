# 存档备份与恢复验收

日期：2026-10-17。本次先完成准备度审视中的存档与程序版本保全，未结束或重建当前试玩局。

## 已实现

- 手动备份、完整性检查、定时备份、定时保留策略、恢复到全新数据库。
- 同一个数据库只读快照生成归档及逐表内容摘要；恢复后比较实际内容，避免只凭文件存在或行数判断成功。
- 每份备份附带当时工作区源码、锁文件、23 个已执行迁移的校验记录。包含尚未提交的项目代码，排除真实环境配置、依赖、缓存与私人根目录文档。
- API 可配置启动备份和每小时备份，默认保留同一个数据库的 48 份定时记录。手动和发布前记录不自动清理。
- 启用自动备份后，通过基本校验的结算发布在写入业务数据前另存恢复点。备份失败则发布事务回滚；没有权限、未满足基本发布条件或相同修订的重复发布不会额外备份。
- 仅提供维护命令，不向网页玩家或主持人开放全服数据库文件。

操作命令、环境配置和限制见 [BACKUP.md](../infrastructure/database/BACKUP.md)。
