# Docker 部署验收

2026-10-21。新增根目录 `compose.yaml` 与独立 `.env.docker.example`，原 `infrastructure/compose.yaml` 保留供源码开发使用。没有修改现有私有 `.env`、原试玩数据库或其他 Docker 项目。

## 部署内容

- Caddy 提供静态网页、API 代理与可选自动 HTTPS；默认仅绑定本机 8080/8443。API、PostgreSQL 17 与 Redis 8 不向宿主机发布端口。
- 迁移服务等待数据库健康，完成后才启动 API；API 通过数据库和 Redis 健康检查后才启动网页。迁移重复执行保持幂等，不重置数据。
- 镜像使用 Node.js 24，依赖安装层可复用。API、worker 移除开发依赖并以非 root 用户运行。worker 当前仅有后台基础连接，按 profile 选用。
- 数据库、缓存、备份与证书使用持久卷。API 内置 PostgreSQL 17 备份工具，默认开启定时备份和发布前恢复点，保留现有完整校验、恢复到新库和源码对应机制。
- 首位主持人通过容器内交互命令建立，密码不回显；数据库已有账号则拒绝，不更新已有账号。没有加入公开初始化接口或默认密码。
- API 默认不信任代理；部署时显式信任 Caddy 一层，避免全部用户被归入同一个登录限流地址，也不直接信任任意多层转发头。
- README 包含本机启动、首位主持人、域名 HTTPS、环境变量、更新、日志、备份恢复、账号恢复和开发测试步骤。

## 实测

- Docker Engine 29.0.1、Compose v2.40.3、Linux 容器；API、Web、worker 三个镜像成功构建。
- 独立随机 Compose 项目执行 `infrastructure/scripts/smoke-deploy.mjs`，使用临时配置、随机端口及全新数据卷；结束清理该项目，不读取真实部署配置。
- 已验证全部迁移、依赖健康、网页首页、静态资源缓存与缺失文件 404、单页路由、未登录 API 401、邀请注册配置、首次主持人创建、重复初始化拒绝、登录和创建双国游戏。
- 已验证手动备份、归档校验及恢复到新库，恢复库的账号与游戏数量符合预期；重启数据库、缓存、API 和网页后原会话与游戏仍可使用。
- 已验证 API 非 root、`pg_dump` 主版本 17、HTTP 与域名 HTTPS 的 Caddy 配置校验；自定义模型基础地址能从部署环境转发，只有网页服务发布宿主机端口。
- 已在 PowerShell 交互终端实际创建演练主持人，密码与确认输入均不回显；可选 worker 启动并连接 Redis。
- 全工作区 227 项单元及页面测试通过（Web 183、API 32、数据库工具 7、配置 5）；类型检查、格式检查与 ESLint 通过。数据库工具测试确认部署 Compose 和公开环境样例进入源码快照，私有 `.env.docker` 不进入。

公网 DNS、80/443 可达性和真实证书签发需要部署时使用实际域名验证，本轮没有向公网开放服务，也没有配置自动发布流水线。
