# 整份回合政策

玩家每回合编写一份政策，在其中增删分项、选择参考分类、自拟标题并填写具体内容，最后一次提交全部分项。分类仅作写作提示，可以重复、组合或跨领域表达，不按类别强制限制政策内容，也不执行建议条数配额。

玩家不再填写“公开意向”。主持人在结算时，根据政策内容和实际影响为每项结算反馈选择接收范围：所属国家与主持人、指定国家与主持人、全体成员（含旁观者），或仅主持人。选择指定国家时只向勾选国家的玩家披露，需要让所属国家收到结果时也须勾选。主持人始终可以查看。

可见范围随结算正式发布生效，草稿不会提前披露。其他国家和旁观者只收到主持人撰写的反馈，不获得政策原文、内部审核意见、原文标题、地图关联目标或讨论权限。地图探索、资源和世界状态仍使用各自的权限规则。反馈勘误沿用发布时的接收范围。历史结算未设置范围时仍为所属国家与主持人可见；旧的公开意向不改变结果权限。可见范围保存在结算 JSON 和发布快照中，无需另加数据库迁移。

“保存整份草稿”只保存玩家编辑稿。新增、删除、改写和调整顺序，均在“提交整份政策”后才更新主持人看到的正式内容。提交前会显示整份确认；空白分项须填写或移除。当前阶段是否允许修改，仍由回合开放状态、截止时间及主持人的补充请求决定。

主持人按“玩家 + 国家 + 回合”查看一整条政策，阅读全部分项后统一批准、拒绝、要求补充或记录解释。一个国家有多名玩家时，各作者的政策分别成份。要求补充只发送一条讨论通知，玩家统一改写后整份重新提交；补充期间不能提前批准。

同一玩家、同一国家、同一回合的旧记录自动汇入同一份政策，不改写原有正式文本和提交历史。内部保留分项 ID，以兼容已有地图目标、讨论链接和结算记录。旧的分项历史单独标注；新正式提交按整份记录，保留提交时的分项顺序。

数据库升级使用 `028_round_policy_submissions.sql`，通过项目的正常迁移或一键更新流程执行。新接口位于 `/api/v1/games/:gameId/quarters/:quarterId/my-policy` 和 `policy-submissions`。整份写入使用一个事务、请求去重和版本校验；任一分项失败时全部回滚。旧接口继续兼容原有链接与工具。

验证包括真实迁移与服务 SQL 的隔离 PGlite 测试，以及玩家多分项编辑、整份提交、失败重试、本地草稿恢复、主持人统一评阅、地图目标和讨论往返的前端测试。PGlite 使用单连接，跨数据库连接的锁竞争仍须使用服务器 PostgreSQL 验证。
