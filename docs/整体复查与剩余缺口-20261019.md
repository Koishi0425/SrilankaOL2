# 整体复查与剩余缺口

日期：2026-10-19。复查的是当前工作区源码、迁移、运行配置和可验证流程，不把设计文档或界面占位当成已完成能力。

## 结论

项目具备主持人带领的小范围试玩闭环，不能称为正式联机版本已经完成。账号管理、备份恢复、结束归档、更正和长文续写都已有实现，但这次检查仍发现成员变更权限、网络重试和部署配置的缺漏，已修复如下。下一阶段仍须补结果交付与成员管理，再完成正式部署和真实玩家连续验收。

## 本次发现并修复

| 问题 | 影响 | 处理 |
| --- | --- | --- |
| 玩家改为观察者仍保留国家；政策读取只核对国家 | 旧成员可能继续读取原国家政策 | 切换观察者时清除国家；政策列表、详情、版本再次核对玩家身份；旧残留绑定也不能绕过。会谈按国家邀请时不把残留绑定的观察者加入 |
| 原作者换到另一国家，旧政策写接口仍只检查作者 | 旧请求可能已修改或提交原国家政策，随后读取才报404 | 修改、保存版本、提交、撤回同时检查当前国家；成员变更和政策操作按回合锁协调。测试核对原文、版本、状态和提交记录确实未变化 |
| “未分配国家”选择项没有实际操作 | 主持人无法撤掉错误分配 | 前后端接受明确的空国家；只允许分配活动玩家，拒绝给主持人／观察者绑定国家 |
| 登录失效只在各面板报错；退出失败无反馈 | 不知道如何重新登录，也可能误以为退出成功 | 全局失效提示与返回登录按钮；先保留正在写的页面，避免直接卸载稿件；退出失败保留会话并提示。旧请求的迟到响应不能影响新登录 |
| 新政策创建缺少请求标识 | 服务器保存成功但响应丢失时，重试可能创建两份 | 增加027迁移；浏览器与本地稿保存创建标识，并发／刷新重试返回同一政策；同标识不同内容拒绝并保留本页文字，提示打开原草稿 |
| Nginx 上传限制低于后端结算限制 | 直接开发访问可保存，经过部署代理后多份长反馈可能被拒绝 | `/api/` 设置16 MiB，与结算接口一致。已核对配置，尚未进行正式 Nginx 容器的端到端上传验收 |
| 私人游戏接口没有统一禁止缓存 | 后续部署缓存层的处理边界不明确 | 所有 `/api/v1/` 响应增加 `Cache-Control: no-store`，真实代理接口已核对 |
| 底层 JSON／媒体类型错误被包装成500 | 客户端格式错误被误报为服务故障 | 返回结构化400／415，保留正常业务错误的原因，不回显请求正文 |
| “公开／相关参与方”文字会让人以为自动分享已生效 | 玩家与主持人对交付范围理解不同 | 改为“公开意向”“请主持人公开／告知相关方”；不改变任何信息权限。正式共享交付仍是下面的未完成项 |

Nginx 的默认大小与413行为按[官方说明](https://nginx.org/en/docs/http/ngx_http_core_module.html#client_max_body_size)核对。当前改的是仓库部署配置，本地试玩仍通过 Vite 代理运行。

## 仍未完成，按实际使用影响排序

### 1. 一轮结果交付需要更完整

玩家现在可看公报和本国政策反馈，但国库／人力收支、部队增减与移动、省份发展等仍分散在国家页、账目和地图。缺少一个按权限整理的本季变化摘要。不能直接公开主持人保存的完整变化列表，其中有敌国与秘密信息。

政策的公开意向目前供主持人裁决，实际政策和私人反馈仍只对本国与主持人开放。没有“选择几个国家 → 共用一段正式反馈 → 各自收取”的交付流程。公报和手工会谈能临时处理，长期会造成重复复制与遗漏。事件、线索及待回应事项也没有独立记录闭环。

### 2. 成员管理尚不完整

已有添加成员、国家分配与解除、主持人协助恢复登录；身份变更仍借重新添加同名成员处理，不够直观。离局、停用本局成员、交接主持人以及普通外交会谈的参与人维护，没有完整正常入口。

普通外交／多人会谈按受邀账号保留，尚无自动随国家继任者移交的模型；政策专属讨论会核对当前国家。正式局宜先固定一人一国。发生继任／换国时，需要明确哪些私人会谈属于个人、哪些属于国家，再实现权限与历史交接，不能只更改顶栏显示名称。

### 3. 开正式剧本仍有重复劳动

新局与历史归档已有闭环，但尚无剧本模板、初始地图及规则配置的导入导出、复制布置。每局仍需手动准备。建设可以通过省份数值表达，建筑和事件实体没有完整专用玩法；独立角色不依附国家的行动也尚未实现。这些不是国家意志试玩的全部阻碍，但不应算已完成内容。

### 4. 还没有正式远程运行环境

正在运行的是本机开发服务。仓库有 Docker／Nginx 骨架，但还缺生产专用配置、HTTPS与域名、服务启动恢复、迁移发布与回退、首个正式主持人初始化、可信代理地址与限速核对、独立备份存储和失败提醒。

现有恢复命令可恢复到新数据库并校验内容，不会自动切换服务。正式切换时还需处理旧备份包含的账号状态、会话和一次性码，避免把已撤销登录或已用码一并恢复为有效。此项属于后续恢复切换流程，不能仅凭文件校验宣称正式运维已完成。

### 5. 缺正式规则与真实规模验收

“界河危机”是演练存档，不能当正式剧本数值依据。仍需一份简版规则明确一季时长、行动截止、资源单位、建设与征募成本、移动及战争裁决、探索／地图交换、冲突政策的处理顺序。网站继续辅助执行主持人的裁决，不自动取代主持人。

当前演示地图12×8，没有用正式玩家数、地图规模和长篇政策量连续跑数轮。大图、长消息历史、多人同时保存、冬季跨年、条约／政策到期、断网恢复和主持人每轮耗时，都应纳入真实内测。
