## 剧本与地图

春汛冲毁界河水渠。河谷王国要求恢复旧水道，海岸公国担忧贸易受损，双方军队在渡口对峙。

地图为 12 × 8 个六角格，南方是水域。河谷省在西侧，界河省在中部，滨海省在东侧。开场双方都知道全图地理、本国详细情况和一部分边境情报，不知道敌军的全部实时状态。

| 开场资料 | 河谷王国 | 海岸公国 |
| --- | --- | --- |
| 省份 | 河谷省 | 界河省、滨海省 |
| 国库 / 人力 | 1000 / 5000 | 1000 / 5000 |
| 军队 | 第一军 1200 人，坐标 4,2 | 守备军 900 人，坐标 6,2 |
| 政府 | 王国，河谷议事会 | 公国，海岸公爵 |
| 界河贸易区影响力 | 6 | 4 |

政治地图以法理归属填底色，实际占领方显示条纹。当前可探测的区域亮着，视野外的已知区域覆盖暗色迷雾，保存最后一次信息；未探明的区域不显示地形。地形符号保留，平原留白。

本国实际控制的地块和仍有兵力的己方部队，向周围提供两格持续视野。全图地理只提供地理记录，不会让远处一直亮着，也不默认提供外国地区、省份的名称与完整轮廓。主持人另外提供的行政资料只标出实际揭示的部分。

## 接着玩秋季

1. 用玩家账号查看地图，检查渡口 5,2 的归属与条纹、海门港 9,3 的河谷第一军；在“回合结果”回看春季与夏季反馈。夏季测试仅移动第一军，没有新增占领。
2. 从地块或省份详情进入政策，写明目标、做法、人员和预算，保存草稿。切换菜单再回来，核对目标与文字是否保留。
3. 有疑问时点“讨论这份政策”，与主持人沟通。需要改变正式方案时修改政策并重新提交，聊天消息本身不替代正式提交。
4. 用主持人账号进入“行动审核”，收齐后锁定并审核；信息不足可要求补充，玩家补充后再次提交。
5. 开始“回合结算”，逐项填写故事反馈、费用、军队/领土/省份变化、外交与行政变化，核对季度经济账单，再保存。
6. 发布前用玩家账号确认变化尚未生效；主持人统一发布后，核对本国结果和地图，再进入下季。

秋季可以选择停战、恢复商路、继续争夺界河省，或追查水道图。无须沿着预设剧情行动。

## 本局规则约定

- **回合与政策**：一季一回合，建议每国一项内政、一项外交、一项军事政策。分类与数量用于整理，允许自由行动；有效性、时序冲突、代价和故事结果由主持人裁决。
- **统一发布**：审核通过表示允许执行，保存结算仍是草稿；正式发布后才执行费用、军队、领土、外交、行政和结果反馈。
- **经济**：本局启用季度经济。税收/生产为基础值 × 系数 10 × 自治保留比例 × 本国合法持有且实际控制的地块占比；人力系数 100。军费每百人 1，行政费每国 5。期初快照固定本季计算依据，本季建设、占领与新改革从下一季影响估算。主持人可以修改实际账单并说明原因。
- **贸易**：采用单个贸易区按影响力分配收益，系数为 3，没有全球贸易流向模拟。宣战或终止通商条约不会自动删除贸易影响力、封锁商路或清零账单；若故事判定商队停运，需要主持人在账单中裁定实际收入，必要时另改影响力。文字反馈不会自行改变数值。
- **外交**：条约、战争与和平结果由主持人记录和发布。没有军事通行或港口停泊许可系统；口头约定及越境纠纷仍可发生并由主持人处理。
- **军事**：本次人数、损失、退守与占领是演练预设，不能据此推导通用胜率。军队移动不会自动完成行军路线、补给、交战与占领。占领改变控制，割让才改变法理归属。
- **政府**：改革可以保存条文、期限与经济效果，不会仅凭一段文字自动推导其他效果。本局水利制度已显式设置生产 +10%。
- **信息**：亮暗由本回合可探测范围决定，不由地块是否被修改决定。未被占领且实际控制的本土持续可见；远方飞地失守、军队撤走后，超出探测范围的区域保留旧记录。敌军在视野内显示估计兵力（默认 ±20%），视野外仅保留旧报告；若看见原驻地已经空了，移除旧军队标记，不追踪其未知的新位置。地理、行政区划与军事动态分别控制，只有地理记录不能定位整省。观察者只读公开内容，主持人预览与对应玩家一致。

## 重新生成独立试局

保留现有试玩无需重跑。需要另一份时，先创建一个空的本机 PostgreSQL 数据库，名称必须以 `srilanka_playtest_` 开头，然后在仓库根目录运行：

```powershell
$env:DATABASE_URL = 'postgres://srilanka:srilanka@localhost:15432/srilanka_playtest_new'
$env:REDIS_URL = 'redis://localhost:16379/12'
$env:PLAYTEST_PASSWORD = '请设置至少八位的演示口令'
pnpm.cmd db:migrate
pnpm.cmd --filter @srilanka/api seed:playtest
```

种子通过游戏服务完整执行春季并开放夏季。已有试局时返回原报告，不重复执行；已有其他游戏时拒绝覆盖。失败后可能保留部分演练数据，应检查原因并改用新的空试玩库。

旧存档采用这次视野规则时，在确认 `DATABASE_URL` 指向目标库后运行 `pnpm.cmd --filter @srilanka/api refresh:vision`，重新计算当前视野；后续由地图与结算操作自动维护。当前试玩库已执行，无需重跑种子或清空游戏。

运行 API 时使用同一 `DATABASE_URL`，设置 `HOST=127.0.0.1`、`PORT=13000`、`WEB_ORIGIN=http://localhost:15173`；Web 设置 `VITE_API_PROXY_TARGET=http://127.0.0.1:13000`，用 Vite 的 `--host 127.0.0.1 --port 15173 --strictPort` 启动。数据库和 Redis 需先运行。
