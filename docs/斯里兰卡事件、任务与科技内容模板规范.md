# 第一章 文档目标

## 1.1 设计目的

本规范用于统一以下内容的定义方式：

- 普通事件；
- 国家专属事件；
- 连续事件链；
- 世界事件；
- 随机事件；
- 任务路线；
- 任务节点；
- 科技定义；
- 自定义研究项目；
- 政策模板；
- 改革模板；
- 状态效果模板；
- AI生成内容草稿。

## 1.2 核心问题

事件、任务和科技不能只保存名称、描述和奖励。

一项正式内容必须能够回答：

1. 什么时候出现；
2. 对谁出现；
3. 玩家能够看到什么；
4. 主持人知道什么；
5. 玩家可以如何回应；
6. 不回应会发生什么；
7. 结果会修改哪些对象；
8. 哪些修改需要计算或随机判定；
9. 哪些信息属于秘密；
10. 内容在回滚后如何失效。

## 1.3 核心原则

内容系统遵守以下原则：

- 模板与实际实例分离；
- 文本描述与状态变更分离；
- 玩家可见内容与主持人内容分离；
- 预设内容与动态生成内容使用统一结构；
- AI生成内容默认属于草稿；
- 所有正式结果必须转换为状态变更集；
- 不要求所有特殊内容都预先硬编码；
- 首版不建立任意脚本式规则语言；
- 内容必须能够被主持人检查、修改和停用；
- 隐藏内容不得提前发送给无权玩家。

# 第二章 内容对象分层

## 2.1 内容定义

内容定义用于描述可重复使用的规则模板，例如：

- 某类地区叛乱事件；
- 某个国家的专属任务路线；
- 一项预设科技；
- 一项治理改革；
- 一种状态效果。

内容定义不代表事件已经在某场游戏中发生。

## 2.2 内容实例

内容实例表示某个模板已经在特定游戏中生成或生效，例如：

- A国在第三季度触发了粮食短缺；
- B国已经开始研究火药武器；
- C国任务路线进入“统一北方”节点；
- D地区获得两季度洪水状态。

## 2.3 内容草稿

内容草稿可以由以下来源生成：

- 主持人手工创建；
- AI生成；
- 剧本导入；
- 玩家自定义行动；
- 系统根据世界状态建议。

草稿不会直接进入正式游戏。

## 2.4 内容版本

内容定义和实例均应具有版本。

正式游戏实例应绑定创建时使用的内容版本，避免模板后续修改改变已经发生的历史。

# 第三章 通用内容字段

## 3.1 基础标识

所有内容定义至少包含：

- 内容ID；
- 内容类型；
- 名称；
- 简称；
- 所属剧本；
- 内容版本；
- 当前状态；
- 创建来源；
- 创建者；
- 创建时间；
- 最后修改时间。

## 3.2 内容状态

定义状态包括：

- Draft；
- ReviewPending；
- Approved；
- Active；
- Disabled；
- Archived；
- Replaced。

实例状态根据具体内容类型分别定义。

## 3.3 分类与标签

内容可以使用：

- 主题分类；
- 系统分类；
- 国家标签；
- 地区标签；
- 文化标签；
- 宗教标签；
- 战争标签；
- 隐秘标签；
- 难度标签；
- 内容来源标签。

标签主要用于检索、候选筛选和AI上下文，不直接等于触发条件。

## 3.4 可见内容

所有正式内容至少区分：

### 玩家标题

玩家能够看到的标题。

### 玩家描述

玩家能够合理知道的事实和背景。

### 主持人标题

主持人后台使用的明确标题。

### 主持人说明

完整原因、隐藏条件、真实情况和裁决建议。

## 3.5 适用范围

内容应明确适用于：

- 所有游戏；
- 某一剧本；
- 某一国家；
- 某类国家；
- 某一地区；
- 某类地形；
- 某类对象；
- 特定任务路线；
- 特定世界状态。

# 第四章 条件结构

## 4.1 条件用途

条件可以用于：

- 事件候选筛选；
- 事件正式触发；
- 任务节点解锁；
- 任务完成；
- 任务失败；
- 科技研究前置；
- 政策可用性；
- 改革推进；
- 选项是否可选；
- 状态效果是否生效。

## 4.2 条件分类

### 对象条件

例如：

- 国家存在；
- 城市未被摧毁；
- 人物仍然存活；
- 军队位于指定地区。

### 属性条件

例如：

- 国库低于指定值；
- 公共秩序低于30；
- 研究能力至少为5；
- 军队人数高于某个阈值。

### 关系条件

例如：

- 两国处于战争状态；
- 国家控制指定城市；
- 人物效忠某国；
- 国家加入某个联盟。

### 历史条件

例如：

- 曾发生某项事件；
- 某任务节点已经完成；
- 某政策已经持续两季度；
- 某城市曾经被占领。

### 时间条件

例如：

- 至少进入第五季度；
- 当前处于战争阶段；
- 距上次同类事件至少三个季度。

### 认知条件

例如：

- 玩家已经发现指定国家；
- 玩家已经获得某条情报；
- 某任务对玩家仍处于隐藏状态。

## 4.3 条件组合

条件应支持：

- All：全部满足；
- Any：任意满足；
- Not：条件不成立；
- Count：满足指定数量；
- Threshold：累计值达到阈值。

## 4.4 结构化条件示例

```json
{
  "type": "All",
  "conditions": [
    {
      "type": "FieldLessThan",
      "objectRef": "targetRegion",
      "field": "publicOrder",
      "value": 30
    },
    {
      "type": "FieldGreaterThan",
      "objectRef": "targetRegion",
      "field": "rebellionRisk",
      "value": 69
    }
  ]
}
```

## 4.5 人工条件

无法结构化的条件可以标记为：

- `HostReviewRequired`；
- `NarrativeCondition`；
- `CustomAdjudication`.

人工条件必须包含清晰的主持人检查说明。

# 第五章 触发与候选机制

## 5.1 候选生成

系统可以根据条件生成内容候选。

候选不等于正式触发。

主持人可以：

- 采用；
- 修改后采用；
- 延后；
- 拒绝；
- 标记一段时间内不再推荐。

## 5.2 正式触发

正式触发后创建内容实例，并记录：

- 目标对象；
- 触发季度；
- 触发阶段；
- 使用模板版本；
- 条件快照；
- 触发来源；
- 可见范围；
- 回应期限。

## 5.3 随机候选

随机事件应采用：

> 条件筛选
> → 权重计算
> → 随机选择
> → 主持人确认

随机选择必须记录：

- 候选集合；
- 权重；
- 随机种子；
- 随机结果；
- 最终是否采用。

## 5.4 主持人直接触发

主持人可以绕过随机选择直接触发内容，但仍应记录：

- 触发原因；
- 目标对象；
- 使用的内容版本；
- 是否属于特殊剧情裁决。

# 第六章 事件模板

## 6.1 事件类型

事件可以分为：

- 普通事件；
- 国家专属事件；
- 地区事件；
- 人物事件；
- 外交事件；
- 军事事件；
- 情报事件；
- 任务事件；
- 世界事件；
- 强制状态事件；
- 主持人自定义事件。

## 6.2 事件模板字段

事件模板至少包括：

- 事件名称；
- 事件类型；
- 玩家标题；
- 玩家描述；
- 主持人说明；
- 适用对象类型；
- 候选条件；
- 触发条件；
- 事件权重；
- 冷却时间；
- 是否唯一；
- 是否计入普通事件上限；
- 回应期限；
- 默认结果；
- 可见范围；
- 事件选项；
- 后续事件；
- 关联任务；
- 关联状态效果。

## 6.3 事件严重程度

事件可以标记：

- Ordinary；
- Important；
- Major；
- Critical。

严重程度影响：

- 页面提示；
- 通知优先级；
- 是否阻塞季度提交；
- 是否需要主持人额外确认。

严重程度不自动决定数值强弱。

## 6.4 事件目标

事件目标可以是：

- 国家；
- 地区；
- 城市；
- 军队；
- 人物；
- 机构；
- 多个国家；
- 整个世界。

事件模板应声明允许的目标类型。

# 第七章 事件实例

## 7.1 实例字段

事件实例至少包含：

- 事件实例ID；
- 来源模板及版本；
- 所属游戏；
- 所属季度；
- 作用对象；
- 触发原因；
- 条件快照；
- 玩家可见内容；
- 主持人完整内容；
- 当前状态；
- 回应截止；
- 当前选择；
- 默认选择；
- 来源世界版本；
- 结果变更集；
- 后续事件。

## 7.2 事件状态

包括：

- Draft；
- Candidate；
- Scheduled；
- Active；
- AwaitingResponse；
- ResponseSubmitted；
- Resolving；
- Resolved；
- Expired；
- Cancelled；
- Invalidated。

## 7.3 事件内容冻结

事件向玩家发布后，玩家已看到的标题、描述和选项应形成实例快照。

后续修改模板不得改变已经发布的事件内容。

## 7.4 事件编辑

事件发布后，主持人仍可以修正实例，但必须：

- 记录修改内容；
- 记录修改原因；
- 通知受影响玩家；
- 不静默改变已经提交回应的选项含义。

# 第八章 事件选项

## 8.1 选项字段

每个选项至少包括：

- 选项ID；
- 玩家标题；
- 玩家说明；
- 主持人完整说明；
- 可选条件；
- 已知成本；
- 已知风险；
- 隐藏影响；
- 是否允许自定义补充；
- 是否需要额外对象；
- 是否需要执行主体；
- 是否需要主持人确认；
- 结果映射。

## 8.2 玩家已知信息

玩家应当看到：

- 可以合理预见的直接成本；
- 明显风险；
- 必要前置条件；
- 需要投入的对象；
- 是否可能引发冲突。

玩家不一定能看到：

- 精确成功概率；
- 隐藏随机结果；
- 他国秘密行动；
- 主持人设置的全部分支。

## 8.3 选项可用性

不可用选项可以：

- 完全隐藏；
- 显示但禁用；
- 显示缺少的条件。

具体方式由事件设计决定。

默认建议显示不可用原因，避免玩家误解系统故障。

## 8.4 自定义回应

事件可以允许玩家输入自定义回应。

自定义回应进入普通玩家行动处理流程。

事件模板应明确：

- 是否允许自定义；
- 是否替代标准选项；
- 是否需要主持人重新定价；
- 是否允许引用其他对象。

# 第九章 事件默认结果

## 9.1 默认结果用途

玩家未在截止前回应时，系统使用默认结果。

## 9.2 默认结果要求

默认结果必须：

- 明确；
- 可执行；
- 不依赖玩家未提供的信息；
- 不产生无法审核的复杂后果；
- 在事件发布时向玩家说明。

## 9.3 无默认结果

关键事件可以不设置自动默认结果。

此时事件会阻塞季度截止，要求主持人处理。

# 第十章 事件结果映射

## 10.1 结果组成

事件结果可以包括：

- 状态变更操作；
- 确定性工具调用；
- 随机判定；
- 新状态效果；
- 新事件；
- 任务推进；
- 消息；
- 玩家认知更新；
- 公共日志；
- 主持人检查项。

## 10.2 结果不直接执行

选项中保存的是结果映射模板。

实际发生时，系统根据当前世界状态生成候选变更集。

## 10.3 参数绑定

结果映射应允许引用：

- 事件目标；
- 回应国家；
- 选中人物；
- 选中城市；
- 执行主体；
- 玩家输入数值；
- 当前季度；
- 工具计算结果。

## 10.4 结果示例

```text
选项：强行征粮

已知成本：
- 地区公共秩序可能下降；
- 获得临时粮食。

结果映射：
- 调用资源计算器；
- 增加国家粮食；
- 降低目标地区公共秩序；
- 添加“强制征粮”状态；
- 增加叛乱检查权重；
- 创建地区历史记录。
```

# 第十一章 事件链

## 11.1 事件链定位

事件链表示由前序事件、选择和世界状态共同推进的一组事件。

## 11.2 事件链字段

包括：

- 事件链名称；
- 起始条件；
- 链内事件；
- 分支关系；
- 终止条件；
- 冷却；
- 可重复性；
- 当前实例状态。

## 11.3 分支

后续事件可以依据：

- 玩家选项；
- 随机结果；
- 状态字段；
- 任务进度；
- 其他国家行动；
- 主持人裁决

进入不同分支。

## 11.4 防止重复

同一链中已经激活的唯一事件不能重复激活。

处于活动状态的完全相同地区叛乱事件不得再次创建。

## 11.5 结束与重启

已结束事件链是否可以再次启动，由模板明确规定。

- 权重修正；

普通事件可以根据以下因素调整权重：

- 治理结构；
- 战争状态；
- 国库；
- 公共秩序；
- 地区数量；
- 人物特质；
- 当前政策；
- 历史事件；

## 12.4 主持人控制

- 锁定必出事件；
- 排除不合适事件；
- 修改事件目标；
- 调整权重；
- 直接创建自定义事件。

- 明确目标；
- 方向性目标；
- 隐藏目标；
- 互斥分支；
- 动态生成节点；
- 失败节点；
- 重构后的后续路线。

## 13.2 路线字段

- 路线名称；
- 所属对象；
- 路线来源；
- 长期目标；
- 玩家可见说明；
- 主持人完整说明；
- 激活条件；
- 关闭条件；
- 可见等级；
- 当前状态；
- 起始节点；
- 节点集合；
- 路线版本。

## 13.3 路线状态

包括：

- Draft；
- Hidden；
- Available；
- Active；
- Suspended；
- Completed；
- Failed；
- Closed；
- Replaced；
- Invalidated。

## 13.4 路线来源

来源可以是：

- 剧本预设；
- 国家背景；
- 玩家长期目标；
- 主持人创建；

- 重大事件；

- 新国家建立。

# 第三十四章 内容验收标准

内容系统达到首版要求时，应满足：

1. 事件模板与实例分离；
2. 已发布事件不会因模板修改静默变化；
3. 玩家文本与主持人文本分离；
4. 事件选项具有明确成本、风险和结果映射；
5. 玩家不回应时有明确处理规则；
6. 自定义回应进入普通行动审核；
7. 任务进度来源于正式世界状态；
8. 科技完成效果能够映射为结构化变更；
9. AI生成内容默认不能直接启用；
10. 隐藏内容不会进入普通玩家接口；
11. 内容结果不直接修改正式世界；
12. 历史实例保留使用的内容版本；
13. 世界回滚能够使相关内容实例失效；
14. 主持人能够预览玩家实际看到的文本；
15. 缺失依赖的导入内容不能直接启用。

## 35.1 基础信息

**事件名称：** 地区性叛乱
**事件类型：** RegionEvent
**目标对象：** 地区
**严重程度：** Major
**是否计入普通事件上限：** 是

## 35.2 候选条件

- 地区叛乱风险处于高等级；
- 当前没有活动中的相同叛乱事件；
- 地区仍具备有效人口；
- 地区不处于已完全废弃状态。

## 35.3 触发概率

实际随机结果只对主持人可见。

## 35.4 玩家描述

## 35.5 选项

### 镇压

已知成本：

- 需要投入军队；
- 可能产生人口和公共秩序损失。

### 谈判

已知风险：

- 可能需要资源或政治让步；
- 谈判期间叛乱继续存在。

### 让步

已知成本：

- 政策或地区权限可能发生变化；
- 可能影响其他地区。

### 自定义处理

允许玩家提交其他方案。

## 35.6 结果映射

结果可以包括：

- 随机判定；
- 人口变化；
- 公共秩序变化；
- 叛乱风险变化；
- 军队伤亡；
- 地区状态效果；
- 后续事件；
- 任务进度；
- 玩家报告。

# 第三十八章 核心结论

SrilankaOL的事件、任务和科技系统不能只是一套文本展示系统。

正式内容必须由以下部分组成：

> 内容定义
> ＋ 条件
> ＋ 玩家视图
> ＋ 主持人视图
> ＋ 选项或节点
> ＋ 结果映射
> ＋ 可见范围
> ＋ 内容版本
> ＋ 状态变更集

其中：

- 事件用于提出当前问题和选择；
- 事件链用于表现选择和世界状态产生的连续结果；
- 任务路线用于表达长期方向和阶段目标；
- 科技用于保存可以研究、完成和解锁的结构化成果；
- 政策和改革用于把玩家自由文本转化为持续世界影响；
- 状态效果负责承载临时和特殊结果；
- AI负责生成候选内容，不负责正式启用和结算；
- 主持人负责审核内容的合理性、强度和可见范围；
- 状态变更系统负责将内容结果写入正式世界。

首版应优先保证内容能够：

- 被创建；
- 被审核；
- 被发布；
- 被回应；
- 被结算；
- 被追踪；
- 被回滚。

而不是优先追求能够自动生成无限数量的事件和任务。
