# 第一章 文档目标

## 1.1 设计目的

本说明书用于定义SrilankaOL需要保存的核心数据对象、对象关系、状态结构、权限信息和历史记录。

数据模型必须支持：

- 六角格世界地图；
- 国家、地区、城市和军队管理；
- 玩家与主持人信息隔离；
- 季度制游戏流程；
- 政策、改革、研究、事件和任务；
- 玩家自定义行动；
- 主持人自然语言修改世界；
- AI生成结构化状态变更；
- 多项行动冲突检测；
- 世界版本、快照和回滚；
- 玩家错误情报和认知状态；
- 自定义属性和非标准状态效果。

## 1.2 设计原则

核心数据模型遵守以下原则：

1. **核心对象使用明确结构。**
   国家、城市、军队、地块等常用对象不得完全依赖自由JSON保存。

2. **特殊内容允许扩展。**
   未预设的游戏内容通过自定义属性、状态效果、对象关系和通用对象保存。

3. **正式状态与草稿分离。**
   AI、脚本和主持人尚未批准的结果不能直接覆盖正式数据。

4. **真实状态与玩家认知分离。**
   玩家看到的信息不是对真实数据库的简单字段隐藏，而是独立的认知投影。

5. **所有变更必须可追溯。**
   任何正式修改均应记录来源、时间、季度、修改人和前后值。

6. **对象当前状态与历史记录分离。**
   当前页面读取当前状态；历史、审计和回滚读取变更与版本记录。

7. **避免过度抽象。**
   首版不建立能够任意定义所有规则的通用规则编程语言。

# 第二章 数据模型分层

SrilankaOL的数据分为四个主要层次。

## 2.1 剧本定义层

剧本定义层保存游戏开始前可以重复使用的内容，包括：

- 世界背景；
- 地图模板；
- 国家模板；
- 地形类型；
- 建筑定义；
- 兵种定义；
- 政策模板；
- 科技框架；
- 通用事件模板；
- 剧本任务路线；
- 初始人物；
- 初始外交关系。

剧本定义层属于“初始配置”，不直接代表某一局游戏当前状态。

## 2.2 游戏实例层

游戏实例层保存某一场实际游戏的正式世界状态，包括：

- 当前国家；
- 当前地图；
- 当前城市；
- 当前军队；
- 当前政策；
- 当前研究；
- 当前事件；
- 当前任务；
- 当前国库和资源；
- 当前领土控制；
- 当前季度状态。

游戏开始时，系统根据剧本定义创建游戏实例。

后续游戏变化只修改实例层，不修改原剧本模板。

## 2.3 玩家认知层

玩家认知层保存每个国家或玩家目前知道的信息，包括：

- 已确认事实；
- 公开信息；
- 侦察结果；
- 间谍情报；
- 传闻；
- 错误情报；
- 过时信息；
- 信息可信度；
- 信息来源；
- 最后更新时间。

同一个真实对象可以为不同玩家生成不同的认知记录。

## 2.4 操作与历史层

操作与历史层保存：

- 玩家行动；
- 主持人整理结果；
- AI结构化草稿；
- 状态变更集；
- 冲突组；
- 世界版本；
- 季度快照；
- 审计记录；
- 结果报告；
- 公共日志；
- 回滚和修正记录。

# 第三章 通用对象标识

## 3.1 世界对象注册表

系统应建立统一的世界对象注册表。

所有可以被引用、编辑、加状态或写入历史的对象，都具有统一的世界对象标识。

主要字段包括：

- `object_id`：全局唯一标识；
- `game_id`：所属游戏；
- `object_type`：对象类型；
- `object_subtype`：可选子类型；
- `display_name`：显示名称；
- `status`：当前状态；
- `created_at`：创建时间；
- `created_by`：创建者；
- `archived_at`：停用或归档时间；
- `current_version`：对象当前版本；
- `metadata`：少量非核心扩展信息。

## 3.2 对象类型

首版主要对象类型包括：

- Game；
- Quarter；
- Country；
- Province；
- Region；
- HexTile；
- City；
- Outpost；
- Building；
- Army；
- MilitaryUnit；
- Character；
- Institution；
- Policy；
- Reform；
- Technology；
- ResearchProject；
- Event；
- MissionRoute；
- MissionNode；
- DiplomaticRelation；
- IntelligenceNetwork；
- IntelligenceReport；
- Action；
- ChangeSet；
- StatusEffect；
- GenericEntity。

## 3.3 对象状态

通用状态可以包括：

- Active：正常生效；
- Inactive：暂时停用；
- Destroyed：已摧毁；
- Completed：已完成；
- Failed：已失败；
- Archived：已归档；
- Draft：草稿；
- Invalidated：已失效；
- Replaced：已被替代。

不同对象可以使用自身更具体的业务状态。

## 3.4 软删除原则

首版原则上不直接物理删除已经进入正式世界的对象。

对象被摧毁、废除或取消时，应修改其状态并保留历史。

只有以下内容可以物理删除：

- 未提交草稿；
- 测试数据；
- 尚未进入正式世界的临时对象；
- 管理员确认无历史价值的错误记录。

# 第四章 游戏与剧本

## 4.1 剧本对象

`Scenario`用于保存可重复使用的游戏初始配置。

主要字段包括：

- 剧本名称；
- 世界背景；
- 开始年份；
- 开始季度；
- 地图模板；
- 启用的规则模块；
- 默认经济参数；
- 默认军事参数；
- 初始国家；
- 初始人物；
- 初始外交关系；
- 剧本可见性；
- 剧本版本。

## 4.2 游戏实例

`Game`表示一场实际运行中的游戏。

主要字段包括：

- 游戏名称；
- 使用的剧本及版本；
- 当前状态；
- 当前年份；
- 当前季度；
- 当前世界版本；
- 主持人；
- 创建时间；
- 开始时间；
- 游戏配置；
- 是否允许新玩家加入；
- 是否启用AI功能；
- 当前地图版本。

游戏状态包括：

- Preparing；
- Running；
- Paused；
- Correcting；
- Completed；
- Archived。

## 4.3 游戏成员

`GameMember`用于关联用户、游戏和角色。

主要字段包括：

- 用户；
- 游戏；
- 成员角色；
- 控制国家；
- 加入时间；
- 当前状态；
- 特殊权限。

成员角色包括：

- Host；
- Player；
- Observer；
- Administrator。

一个玩家首版通常控制一个国家，但数据结构不应强制限制一名用户永远只能控制一个国家。

# 第五章 季度与流程状态

## 5.1 季度对象

`Quarter`表示一个实际游戏回合。

主要字段包括：

- 游戏；
- 游戏年份；
- 季节；
- 季度序号；
- 当前流程状态；
- 开始时间；
- 行动截止时间；
- 发布时间；
- 基准世界版本；
- 发布世界版本；
- 是否发生回滚；
- 修正版本号。

## 5.2 季度流程状态

季度状态包括：

- Preparing；
- EventResponse；
- ActionSubmission；
- Locked；
- HostReview；
- AIProcessing；
- Resolving；
- PendingPublication；
- Published；
- DisputeReview；
- Correcting；
- Completed。

## 5.3 季度阶段

除季度总体状态外，正式变更还需要记录其业务发生阶段：

1. QuarterStart；
2. ForcedState；
3. EventResponse；
4. Diplomacy；
5. PolicyAndReform；
6. Intelligence；
7. Construction；
8. Research；
9. Recruitment；
10. MilitaryMovement；
11. Battle；
12. SiegeAndOccupation；
13. CustomResolution；
14. QuarterEnd。

阶段顺序用于处理同期行动冲突。

# 第六章 地图与地理对象

## 6.1 地图

`Map`保存一场游戏使用的地图配置。

主要字段包括：

- 游戏；
- 地图名称；
- 宽度；
- 高度；
- 六角格坐标方向；
- 地图投影说明；
- 默认缩放范围；
- 地图资源版本。

## 6.2 六角格

`HexTile`是地图的基础空间单位。

核心字段包括：

- 六角格坐标；
- 所属地图；
- 所属地区；
- 地形类型；
- 海拔或地形补充信息；
- 是否陆地；
- 是否可通行；
- 基础移动消耗；
- 当前合法所有者；
- 当前实际控制者；
- 当前占领者；
- 探索状态；
- 道路等级；
- 河流和水域连接；
- 当前城市；
- 当前主要据点；
- 当前特殊状态。

应区分：

- `legal_owner_country_id`：法理或正式领有国；
- `controller_country_id`：当前实际控制国；
- `occupier_country_id`：战争中的占领国。

## 6.3 相邻关系

六角格相邻关系原则上可根据坐标计算。

特殊地图边界、海峡、传送门等非标准连接，通过`TileConnection`记录。

连接字段包括：

- 起点地块；
- 终点地块；
- 连接类型；
- 是否双向；
- 移动修正；
- 使用条件；
- 可见范围；
- 当前状态。

## 6.4 地形类型

`TerrainType`属于定义数据。

主要字段包括：

- 名称；
- 图标；
- 基础移动消耗；
- 战斗修正；
- 补给修正；
- 是否允许建设城市；
- 是否允许道路；
- 默认资源类型；
- 说明。

具体战斗数值可在后续战斗系统中补充。

## 6.5 省份

`Province`主要用于地理组织。

核心字段包括：

- 名称；
- 所属地图；
- 包含地区；
- 剧本地理说明；
- 当前主要控制国；
- 法理归属；
- 显示样式。

省份控制状态可以由下属地区推导，也可以保存缓存字段。

## 6.6 地区

`Region`是经济、人口和行政的主要单位。

核心字段包括：

- 名称；
- 所属省份；
- 包含地块；
- 主要城市；
- 法理所有者；
- 实际控制者；
- 占领者；
- 总人口；
- 发展等级；
- 税收基础值；
- 资源基础值；
- 公共秩序准确值；
- 叛乱风险准确值；
- 当前显示等级；
- 征募能力；
- 补给容量；
- 当前地区状态；
- 是否具备完整行政功能。

地区对玩家展示的公共秩序、叛乱风险和经济信息，应通过权限和认知层处理，而不是直接暴露准确字段。

# 第七章 城市、据点与建筑

- 所在地块；
- 所属地区；
- 法理所有者；
- 当前控制者；
- 当前占领者；
- 城市状态；
- 建筑槽位总数；
- 已使用建筑槽位；
- 当前建设项目；

- 城防状态；
- 城门状态；
- 城市补给状态；
- 驻军；
- 建立季度；
- 被占领季度。

城市状态可以包括：

- Normal；
- UnderConstruction；
- Besieged；
- Occupied；
- Damaged；
- Abandoned；
- Destroyed。

- MagicSite；
- ObservationPost；

主要字段包括：

- 名称；

- 所在地块；

- 建设开始季度；

- 当前维护状态；

## 7.5 建设项目

主要字段包括：

- 建设对象；

- 项目类型；
- 总需求进度；
- 当前进度；
- 开始季度；
- 预计完成季度；
- 已支付费用；
- 已消耗资源；
- 当前状态；
- 暂停原因；
- 关联玩家行动。

## 8.4 机构

`Institution`表示政府、议会、军方、宗教团体、商会、研究组织或秘密组织。

## 8.5 人物和机构占用

- 执行主体；

- 结束阶段；

- 是否排斥其他任务。

该结构用于检测同一人物或机构被重复用于多个冲突行动。

# 第九章 经济、收入与债务

## 9.1 经济流水

`LedgerEntry`记录所有正式经济变化。

字段包括：

- 国家；
- 季度；
- 交易类型；
- 金额；
- 资源类型；
- 收入或支出；
- 来源对象；
- 关联行动；
- 关联变更集；
- 发生阶段；
- 备注。

国库当前余额可以缓存，但必须能够由流水和初始值复核。

## 9.2 债务

`Debt`记录具体债务。

主要字段包括：

- 借款国家；
- 债权方；
- 初始本金；
- 当前本金；
- 利率；
- 开始季度；
- 到期条件；
- 当前状态；
- 最近计息季度；
- 是否发生资本化；
- 关联协议。

## 9.3 周期收入与维护

持续收入和支出通过`RecurringFinancialRule`记录，例如：

- 税收；
- 军队维护；
- 建筑维护；
- 情报网络维护；
- 外交协议费用；
- 特殊政策支出。

字段包括：

# 第二十一章 世界版本与快照

## 21.1 世界版本

`WorldVersion`表示正式世界状态的一次一致版本。

每次成功提交正式变更集后，生成新的世界版本。

主要字段包括：

- 游戏；
- 版本号；
- 上一版本；
- 来源变更集；
- 所属季度；
- 创建时间；
- 创建者；
- 版本说明；
- 是否有效。

## 21.2 对象版本

每个世界对象记录其当前版本。

必要时通过`ObjectVersion`保存对象的历史快照：

- 对象；
- 世界版本；
- 完整结构化状态；
- 生效时间；
- 失效时间。

不要求每次修改都复制整个世界数据库。

## 21.3 季度快照

`QuarterSnapshot`至少保存：

- 季度开始快照；
- 行动截止快照；
- 结算完成快照；
- 正式发布快照。

快照字段包括：

- 所属季度；
- 快照类型；
- 世界版本；
- 创建时间；
- 数据校验值；
- 当前状态。

## 21.4 回滚

季度回滚时：

1. 选择季度开始快照；
2. 恢复正式世界版本；
3. 标记后续变更集失效；
4. 标记相关叙事失效；
5. 保留审计记录；
6. 重新生成修正版世界版本。

## 23.3 权限与认知的区别

权限决定系统是否允许读取真实字段。

例如：

- 玩家无权读取敌军精确人数；
- 但可以通过认知层看到“约一万人”。

系统不得先把精确人数传给前端，再依赖界面隐藏。

# 第二十六章 核心约束

## 26.1 地图约束

- 每个六角格必须属于一个地图；
- 陆地格原则上必须属于一个地区；
- 城市必须位于一个六角格；
- 一个六角格首版默认最多存在一座主要城市；
- 军队只能位于有效地图位置；
- 被摧毁对象不能继续作为正常行动主体。

## 26.2 国家约束

- 国家国库不得在无债务或特殊规则的情况下无解释地长期为负；
- 已灭亡国家不能提交普通国家行动；
- 玩家只能修改自己有权限的行动草稿；
- 玩家不能直接修改正式国家状态。

## 26.3 建设约束

- 城市同时只能存在一个默认建设项目；
- 建筑槽位不能超过城市容量；
- 被占领城市默认不能正常启动普通建设；
- 科研建筑建成当季不产生研究能力。

## 26.4 研究约束

- 研究项目不能超过有效槽位；
- 研究能力分配总量不能超过国家当季度可用研究能力；
- 研究能力不能跨季度作为通用库存保存；
- 未满足前置条件的项目不能获得有效进度。

## 26.5 军事约束

- 同一地区同一季度最多存在一个有效军事人员项目；
- 同一军队不能同时位于多个地块；
- 同一军事单位不能同时属于多支军队；
- 补给中断军队不能正常补员；
- 同一人物不能同时担任明显冲突的军事任务。

## 26.6 变更约束

- 正式世界只能通过批准后的变更集修改；
- 变更集提交时必须验证世界版本；
- 关键操作失败时整个原子变更集回滚；
- 冲突变更不能按照创建顺序直接覆盖；
- AI不能直接执行正式提交。

# 第二十九章 数据模型核心结论

SrilankaOL的数据模型不能只保存“现在地图上有什么”。

系统还必须同时保存：

1. **真实世界当前状态；**
2. **玩家认为世界是什么状态；**
3. **玩家和主持人准备如何修改世界；**
4. **世界过去为什么变成现在这样。**

因此，首版核心数据体系应由以下部分共同组成：

> 固定核心对象
> ＋ 类型化自定义属性
> ＋ 状态效果
> ＋ 动态对象关系
> ＋ 玩家认知数据
> ＋ 原子状态变更集
> ＋ 世界版本与快照
> ＋ 叙事版本和审计记录

其中：

- 固定核心对象保证规则计算和界面展示稳定；
- 自定义属性保证玩家自由行动不受预设字段限制；
- 状态效果用于保存临时和特殊影响；
- 玩家认知层负责战争迷雾和错误情报；
- 变更集负责将自然语言裁决转换为正式数据；
- 世界版本负责冲突检测和季度回滚；
- 审计记录保证所有主持人和AI操作可以追溯。

这套数据模型是后续数据库设计、API规范、网页地图、主持人编辑器和世界管理 Agent 的共同基础。
