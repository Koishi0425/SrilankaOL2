# SrilankaOL 主持人季度结算流程说明书

**文档版本：** v0.1
**文档性质：** 主持人操作流程
**前置文档：**《SrilankaOL 核心游戏规则与主持人裁决说明书》
**适用范围：** 普通季度回合的准备、行动审核、冲突处理、结果生成、发布与回滚

---

# 第一章 文档目的

## 1.1 使用目的

本说明书用于帮助主持人按照统一顺序完成每个季度的游戏结算。

本说明书主要解决以下问题：

- 每个季度先处理什么；
- 玩家需要提交什么；
- 主持人需要检查什么；
- AI在哪些阶段参与；
- 系统负责执行哪些计算；
- 多国行动发生冲突时如何处理；
- 结果如何集中发布；
- 出现错误时如何回滚。

## 1.2 使用原则

主持人应遵守以下原则：

1. 先确认事实，再进行计算；
2. 先整理行动，再判断结果；
3. 先处理相互依赖的行动，再处理独立行动；
4. 系统计算不能代替主持人裁决；
5. AI建议不能直接成为正式结果；
6. 秘密行动与公开行动分开处理；
7. 同一季度结果原则上统一发布；
8. 重大错误应回滚整个季度。

---

# 第二章 季度状态

## 2.1 季度阶段状态

每个季度应具有以下状态之一：

- 准备中；
- 事件回应中；
- 行动提交中；
- 已截止；
- 主持人整理中；
- AI处理中；
- 结算中；
- 待发布；
- 已发布；
- 异议处理中；
- 正在修正；
- 已完成。

## 2.2 状态权限

### 准备中

主持人可以修改季度基础状态。

玩家不能提交正式行动。

### 事件回应中

玩家可以查看本国季度事件并进行回应。

### 行动提交中

玩家可以提交或修改：

- 政策；
- 外交；
- 建设；
- 研究；
- 军事；
- 情报；
- 事件回应；
- 自定义行动。

### 已截止

玩家不能自行修改行动。

主持人可以要求补充或修正。

### 结算中

系统与主持人处理所有行动。

玩家只能查看已经公开的信息。

### 已发布

玩家可以查看本季度结果，并在规定时间内提出异议。

# 第三章 季度总体流程

每个季度按照以下九个阶段进行：

1. 上季度收尾；
2. 季度开始状态更新；
3. 季度事件生成；
4. 玩家回应与行动提交；
5. 行动截止与完整性检查；
6. 主持人整理与AI结构化；
7. 冲突解析与正式结算；
8. 结果审核与集中发布；
9. 异议处理与季度归档。

---

# 第四章 第一阶段：上季度收尾

## 4.1 阶段目标

确认上一季度所有持续结果已经正确记录，并处理跨季度状态。

## 4.2 主持人检查项

主持人应检查：

- 上季度结果是否已经正式发布；
- 是否存在未处理异议；
- 是否存在正在修正的结果；
- 是否存在跨季度围城；
- 是否存在持续事件链；
- 是否存在未完成建设；
- 是否存在未完成研究；
- 是否存在持续政策；
- 是否存在持续改革；
- 是否存在军队撤退或追击；
- 是否存在持续情报行动；
- 是否存在潜伏或维护中的情报网络；
- 是否存在债务、破产或停战状态；
- 是否存在下一季度必须触发的事件。

## 4.3 系统操作

系统应自动生成上一季度遗留对象清单，包括：

- 持续项目；
- 持续状态；
- 未完成行动；
- 下一季度生效效果；
- 下一季度到期效果；
- 必须进行维护的对象；
- 需要主持人处理的异常状态。

## 4.4 阶段输出

本阶段结束后，应形成：

- 上季度完成确认；
- 本季度遗留状态清单；
- 本季度强制处理事项清单。

---

# 第五章 第二阶段：季度开始状态更新

## 5.1 阶段目标

确定本季度开始时的正式世界状态。

## 5.2 时间与季节更新

系统更新：

- 当前年份；
- 当前季度；
- 季节效果；
- 冬季补给修正；
- 春季或秋季收入结算标记；
- 剧本规定的季节性效果。

## 5.3 持续效果更新

系统检查并处理：

- 新建建筑是否开始生效；
- 科研建筑是否开始产生研究能力；
- 新政策是否开始生效；
- 改革是否完成；
- 临时效果是否到期；
- 建筑是否因占领或维护不足失效；
- 情报网络是否支付维护费；
- 军队是否需要支付维护费；
- 债务利息是否需要结算；
- 停战期是否到期；
- 其他跨季度效果。

## 5.4 收入与支出

### 春季和秋季

系统结算：

- 普通税收；
- 常规资源收入；
- 剧本规定的周期性收入。

### 每个季度

系统结算：

- 军队维护；
- 情报网络维护；
- 特殊建筑维护；
- 债务利息；
- 其他持续支出。

## 5.5 资金不足处理

当国库不足时，主持人应检查：

- 是否允许自动借债；
- 是否存在优先支付顺序；
- 哪些军队维护不足；
- 哪些建筑停止运作；
- 哪些情报网络进入异常状态；
- 是否触发破产检查；
- 是否需要生成相关事件。

## 5.6 军队状态更新

系统更新：

- 军队人数；
- 军队士气上限；
- 当前士气；
- 补给状态；
- 所在位置；
- 撤退状态；
- 围城状态；
- 维护状态；
- 可用移动力。

## 5.7 地区状态更新

系统更新：

- 人口；
- 发展状态；
- 税收与资源；
- 公共秩序；
- 叛乱风险；
- 占领状态；
- 城市功能；
- 特殊据点状态。

## 5.8 阶段输出

本阶段结束后，应形成：

- 本季度正式初始状态；
- 国家资源与国库状态；
- 军队状态；
- 地区状态；
- 持续项目状态；
- 本季度可用政策、建设、研究和行动条件。

---

# 第六章 第三阶段：季度事件生成

## 6.1 阶段目标

在玩家提交本季度行动前，生成其可以回应的普通随机事件。

## 6.2 事件候选筛选

系统根据以下条件生成候选事件：

- 国家状态；
- 地区状态；
- 政体；
- 政策；
- 改革；
- 战争；
- 外交；
- 科技；
- 宗教和文化背景；
- 人物与机构；
- 历史行动；
- 事件冷却；
- 任务路线；
- 剧本条件。

## 6.3 普通事件上限

每个国家每季度最多正式触发一个普通随机事件。

系统可以生成多个候选事件，但只能选择最多一个正式触发。

没有合适事件时，可以不触发。

## 6.4 主持人审核

主持人应检查：

- 事件是否符合当前状态；
- 是否与近期事件重复；
- 是否泄露隐藏信息；
- 是否对某一玩家明显不公平；
- 是否会造成过多额外处理；
- 是否与任务事件或重大事件冲突；
- 事件选项是否具有合理后果。

## 6.5 国家专属事件

若候选事件与国家长期方向、历史行为或任务路线高度相关，可以优先选用国家专属事件。

## 6.6 事件发布

事件应向玩家显示：

- 事件背景；
- 当前可知事实；
- 可选回应；
- 可预见成本；
- 可预见主要风险；
- 回应期限；
- 未回应时的默认处理方式。

隐藏后果不公开。

## 6.7 阶段输出

本阶段结束后，每个国家应处于以下状态之一：

- 已获得普通事件；
- 本季度无普通事件；
- 正在处理任务或重大事件。

---

# 第七章 第四阶段：玩家回应与行动提交

## 7.1 阶段目标

收集玩家对本季度的完整国家决策。

## 7.2 玩家可提交内容

玩家可以提交：

- 事件回应；
- 政策；
- 改革；
- 外交行动；
- 建设项目；
- 城市建立；
- 地区开发；
- 研究项目；
- 研究能力分配；
- 征募；
- 补员；
- 军队编组；
- 军队移动；
- 战术；
- 围城行动；
- 情报行动；
- 情报网络维护、升级或潜伏；
- 自定义行动；
- 其他合理操作。

## 7.3 提交可见范围

每项行动应标记：

- 公开；
- 仅对指定国家公开；
- 仅对本国和主持人公开；
- 完全秘密；
- 结果公开但过程保密。

## 7.4 主持人过程检查

在截止前，主持人可以提前指出：

- 行动目标不清楚；
- 执行主体缺失；
- 行动范围过大；
- 行动自相矛盾；
- 使用了不存在的资源；
- 同一主体被重复使用；
- 行动明显无法执行；
- 需要玩家补充的关键条件。

主持人不应在此阶段提前泄露其他玩家行动。

## 7.5 玩家修改

在主持人宣布截止前，玩家可以修改尚未产生即时结果的行动。

已经即时执行并产生公开影响的内容不能无条件撤回。

---

# 第八章 第五阶段：截止与完整性检查

## 8.1 宣布截止

主持人宣布截止后：

- 玩家不能自行编辑行动；
- 系统锁定当前提交版本；
- 后续修改必须由主持人发起。

## 8.2 国家行动清单

系统为每个国家生成本季度行动清单，按以下类别整理：

- 事件；
- 政策；
- 改革；
- 外交；
- 经济与建设；
- 研究；
- 人口与军队；
- 军事移动；
- 情报；
- 自定义行动。

## 8.3 完整性检查

主持人应逐国检查：

- 是否存在无法理解的行动；
- 是否存在遗漏的目标对象；
- 是否存在资源不足；
- 是否存在行动主体冲突；
- 是否存在时间冲突；
- 是否存在相互排斥的项目；
- 是否存在超过建筑槽位的建设；
- 是否存在超过研究槽位的项目；
- 是否存在地区征募与补员冲突；
- 是否存在同一军队互相矛盾的命令；
- 是否存在违反信息权限的行动。

## 8.4 补充与修正

仅在以下情况下要求玩家补充：

- 核心目标不明确；
- 目标对象不明确；
- 行动无法结算；
- 行动存在直接矛盾；
- 可能新增重大成本或风险；
- 公开或秘密性质不明确。

普通格式问题由主持人直接整理。

---

# 第九章 第六阶段：主持人整理与AI结构化

## 9.1 主持人初步整理

主持人首先将自然语言行动整理为明确描述。

主持人应保留：

- 玩家核心目标；
- 玩家指定的方法；
- 玩家指定的投入；
- 玩家要求的保密范围；
- 玩家明确不愿接受的条件。

## 9.2 AI输入内容

主持人向AI提供：

- 整理后的行动；
- 当前世界状态；
- 相关规则；
- 可用资源；
- 执行主体；
- 已知对抗条件；
- 允许AI使用的信息范围。

秘密行动不得向无关玩家的处理上下文泄露。

## 9.3 AI结构化输出

AI应生成：

- 行动名称；
- 行动类别；
- 行动目标；
- 执行主体；
- 目标对象；
- 前置条件；
- 实施方式；
- 所需时间；
- 所需成本；
- 所占用对象；
- 风险；
- 可能结果；
- 对抗方式；
- 判定建议；
- 信息公开范围；
- 相关规则。

## 9.4 主持人审核

主持人应检查AI是否：

- 改变玩家原意；
- 擅自增加重大成本；
- 擅自扩大目标；
- 擅自创造资源；
- 泄露秘密信息；
- 将建议写成事实；
- 给出不符合世界观的结果；
- 与其他规则冲突。

## 9.5 玩家再次确认

只有出现以下情况时，才需要玩家再次确认：

- 目标发生实质改变；
- 主要方式发生改变；
- 新增重大成本；
- 新增重大风险；
- 行动时间明显延长；
- 保密性质发生改变；
- 行动范围明显缩小或扩大。

## 9.6 正式行动单

主持人批准后，系统生成正式行动单。

正式行动单成为本季度唯一有效结算依据。

# 第十章 第七阶段：冲突解析

## 10.1 处理原则

不同国家行动互相影响时，不应按提交先后直接决定结果。

应将所有相关行动放入同一冲突组中统一处理。

## 10.2 冲突组类型

冲突组可以包括：

- 外交冲突；
- 领土开发冲突；
- 军队移动冲突；
- 战斗冲突；
- 围城冲突；
- 情报与反间谍冲突；
- 竞争建设；
- 竞争招募；
- 人物或机构争夺；
- 多国事件；
- 其他相互依赖行动。

## 10.3 冲突组输入

每个冲突组应包含：

- 所有相关正式行动单；
- 行动主体；
- 行动时间；
- 地理位置；
- 情报条件；
- 资源投入；
- 相关政策；
- 相关人物和机构；
- 随机因素；
- 特殊规则。

## 10.4 同时行动

无法合理确定明确先后顺序时，默认按照同时行动处理。

系统或主持人可以使用以下因素判断局部先后：

- 移动力；
- 距离；
- 地形；
- 准备程度；
- 情报优势；
- 先前已经存在的控制；
- 特殊行动效果；
- 其他合理因素。

## 10.5 秘密行动冲突

秘密行动冲突必须单独处理。

玩家只能看到其国家能够观察到的结果。

主持人应避免在结果说明中暴露：

- 敌方具体行动原文；
- 情报网络来源；
- 未被发现的执行主体；
- 隐藏判定数值。

# 第十一章 第八阶段：正式结算顺序

同一季度的正式结算建议按照以下顺序进行。

---

## 11.1 第一顺位：强制状态与即时事件

优先处理：

- 上季度遗留的强制结果；
- 破产；
- 政变；
- 统治者死亡或继承；
- 必须立即处理的灾害；
- 强制撤退；
- 已满足条件的自动投降；
- 其他会改变国家行动基础的状态。

这些结果可能使部分玩家行动失效或需要重新解释。

---

## 11.2 第二顺位：事件回应

处理玩家对季度开始事件的选择。

优先结算会立即影响其他行动的结果，例如：

- 获得或失去资源；
- 政策立即生效；
- 人物出现或离开；
- 地区状态变化；
- 军队受到影响；
- 外交关系变化。

仅在季度末生效的结果可以暂缓记录。

---

## 11.3 第三顺位：外交与公开协议

处理：

- 结盟；
- 宣战；
- 停战；
- 和平协议；
- 通行权；
- 贸易协议；
- 保障；
- 附属关系；
- 联姻；
- 领土交易；
- 其他公开协议。

需要双方同意的行动，必须检查双方正式提交内容是否一致。

秘密协议只记录相关国家和主持人可见内容。

---

## 11.4 第四顺位：政策与改革

处理：

- 新政策启动；
- 政策到期；
- 政策替换；
- 政策被迫终止；
- 改革启动；
- 改革推进；
- 改革完成；
- 制度变化。

政策与改革可能影响后续建设、研究、征募、外交和军事结算。

---

## 11.5 第五顺位：情报准备与反间谍

先处理会影响本季度其他行动认知的情报行为，例如：

- 地图侦察；
- 军队侦察；
- 情报核实；
- 反间谍调查；
- 网络监视；
- 虚假情报投放；
- 情报网络升级；
- 网络暴露。

通过本阶段获得的信息，通常不能让玩家在截止后重新修改本季度行动，但可以影响主持人对行动过程和结果的判断。

---

## 11.6 第六顺位：建设与地区开发

处理：

- 城市建设；
- 建筑项目；
- 城市建立；
- 道路；
- 特殊据点；
- 地区开发；
- 竞争开发；
- 建设取消；
- 建筑损毁或停用。

建设进度按照本季度有效条件计算。

本季度完成的科研建筑从下一个完整季度开始产生研究能力。

---

## 11.7 第七顺位：研究

处理：

- 研究能力生成；
- 研究槽位状态；
- 玩家分配方案；
- 项目前置条件；
- 项目季度进度；
- 项目暂停；
- 项目完成；
- 溢出研究能力；
- 科技解锁。

若某项研究依赖本季度刚建成的科研建筑，则该建筑本季度不提供研究能力。

若项目依赖本季度早期已经获得的事件条件或政策效果，则根据其生效规则判断是否生效。

---

## 11.8 第八顺位：征募、补员与编制

处理：

- 地区军事人员项目；
- 新部队征募；
- 现有部队补员；
- 人口扣除；
- 费用结算；
- 单位形成；
- 军队合并；
- 军队拆分；
- 军队编组。

新单位和新补充人员从下一个完整季度开始支付维护费。

---

## 11.9 第九顺位：军事移动

处理所有军队路线。

系统应：

1. 读取所有正式移动命令；
2. 计算每支军队有效移动力；
3. 应用道路和地形消耗；
4. 按抽象移动步骤推进；
5. 检查拦截；
6. 检查敌军相遇；
7. 检查边界遭遇；
8. 检查补给路线；
9. 生成战斗与围城列表。

军队一旦进入战斗，其原路线默认终止。

---

## 11.10 第十顺位：战斗

对每场战斗分别处理：

1. 参战军队；
2. 战斗类型；
3. 临时攻守关系；
4. 地形；
5. 战场宽度；
6. 前线、后线和预备队；
7. 指挥官；
8. 玩家战术；
9. 火力阶段；
10. 冲击阶段；
11. 循环阶段；
12. 士气崩溃；
13. 撤退；
14. 追击；
15. 伤亡；
16. 战斗结果。

同一阶段伤害同时结算。

详细公式由独立战斗模拟器提供。

---

## 11.11 第十一顺位：围城与占领

处理：

- 新围城建立；
- 围城季度进度；
- 封锁；
- 守军状态；
- 城市补给；
- 城防缺口；
- 强攻；
- 自动投降；
- 占领；
- 建筑失效；
- 地区经济限制。

围城可以延续至下一季度。

---

## 11.12 第十二顺位：其他自定义行动

处理尚未在标准系统中覆盖的行动。

结算时应依据正式行动单中的：

- 目标；
- 主体；
- 投入；
- 时间；
- 风险；
- 对抗；
- 判定方式。

结果可以是：

- 完全成功；
- 部分成功；
- 成功但产生代价；
- 失败但未暴露；
- 失败并引发反制；
- 暂无进展；
- 意外结果。

---

## 11.13 第十三顺位：季度末状态更新

统一处理：

- 资源变化；
- 国库变化；
- 人口变化；
- 地区控制；
- 公共秩序；
- 叛乱风险；
- 士气；
- 补给；
- 战争疲劳；
- 外交关系；
- 人物和机构状态；
- 任务路线进度；
- 事件链状态；
- 情报可信度；
- 情报时效；
- 持续效果剩余时间。

---

# 第十二章 随机判定

## 12.1 使用条件

仅在规则和已知条件无法直接确定结果时使用随机判定。

## 12.2 判定过程

随机判定应包括：

- 基础结果范围；
- 正向因素；
- 负向因素；
- 隐藏因素；
- 随机结果；
- 主持人修正；
- 最终结果。

## 12.3 玩家可见信息

玩家可以看到：

- 是否进行了随机判定；
- 其国家合理知道的主要影响因素；
- 最终可观察结果。

玩家默认不能看到：

- 隐藏概率；
- 敌方秘密修正；
- 主持人后台判定；
- 未被发现的情报因素。

## 12.4 主持人修改

主持人可以修改或重掷结果，但必须记录：

- 原始结果；
- 修改后的结果；
- 修改原因；
- 修改时间；
- 受影响对象。

该记录默认不向玩家公开。

---

# 第十三章 结果生成

## 13.1 结果层级

每个国家的季度结果应分为：

1. 国家总览；
2. 事件结果；
3. 政策与改革；
4. 外交；
5. 经济与资源；
6. 建设；
7. 研究；
8. 军队与战争；
9. 地区变化；
10. 情报；
11. 任务路线；
12. 下季度待处理事项。

## 13.2 公开结果与私密结果

### 公开结果

可以被其他国家观察到的内容，例如：

- 战争结果；
- 领土变化；
- 公开政策；
- 城市建立；
- 正式外交协议；
- 明显军队调动；
- 公开事件。

### 私密结果

仅向本国玩家显示：

- 国库；
- 内部政策细节；
- 研究进度；
- 未公开任务；
- 秘密外交；
- 情报结果；
- 秘密行动；
- 内部人物与机构变化。

### 主持人结果

主持人额外看到：

- 精确隐藏数值；
- 随机结果；
- 秘密对抗；
- 错误情报真实情况；
- 未公开行动；
- 审计记录。

## 13.3 结果说明

重要结果应说明：

- 发生了什么；
- 为什么发生；
- 产生了哪些直接变化；
- 有哪些持续效果；
- 玩家下一季度可以如何回应。

不应公开不属于该玩家的信息。

---

# 第十四章 发布前审核

## 14.1 全局一致性检查

主持人应检查：

- 同一领土是否被重复分配；
- 同一军队是否出现在多个位置；
- 国库和资源是否重复扣除；
- 人口是否正确扣除；
- 建筑槽位是否超限；
- 研究槽位是否超限；
- 外交协议双方记录是否一致；
- 战争状态是否一致；
- 占领状态是否一致；
- 时间和季度是否一致。

## 14.2 信息隔离检查

主持人应检查结果是否泄露：

- 他国政策原文；
- 秘密外交；
- 间谍身份；
- 情报网络；
- 未被发现的军队；
- 隐藏任务；
- 主持人秘密判定；
- 错误情报的真实答案。

## 14.3 叙事一致性检查

AI生成的叙事应符合：

- 已发生的事实；
- 世界观；
- 国家身份；
- 玩家行动；
- 结果严重程度；
- 时间顺序。

叙事不得创造未发生的重大事实。

## 14.4 玩家可操作性检查

每份结果应让玩家明确知道：

- 当前国家状态；
- 本季度发生的主要变化；
- 哪些问题仍在持续；
- 下季度有哪些需要回应的事项。

---

# 第十五章 结果集中发布

## 15.1 发布条件

满足以下条件后才能发布：

- 所有主要冲突已经结算；
- 各国结果已经生成；
- 全局状态一致；
- 信息隔离检查完成；
- 主持人最终批准。

## 15.2 发布方式

结果原则上同时发布。

系统可以按照国家分别展示，但正式发布时间应一致。

## 15.3 世界公共日志

系统可以生成公共世界日志，记录：

- 正式战争；
- 战斗结果；
- 和平协议；
- 领土变化；
- 公开外交；
- 公开政策；
- 重大建设；
- 重大事件；
- 其他所有国家均可观察的信息。

## 15.4 国家私密报告

每个玩家收到本国完整报告。

报告不得包含其国家尚未获得的他国信息。

---

# 第十六章 异议与修正

## 16.1 可提出异议的情况

玩家可以针对以下问题提出异议：

- 行动被错误理解；
- 规则被错误应用；
- 资源计算错误；
- 地图位置错误；
- 结果与已批准行动单矛盾；
- 信息被错误公开；
- 其他客观结算错误。

玩家不能仅因结果不利要求重算。

## 16.2 主持人检查

主持人应核对：

- 玩家原始提交；
- 主持人整理内容；
- AI结构化方案；
- 正式行动单；
- 相关规则；
- 随机记录；
- 最终结果。

## 16.3 局部修正与季度回滚

仅当错误不影响其他国家和其他系统时，可以局部修正。

若错误影响：

- 多国决策；
- 战争结果；
- 领土；
- 资源链；
- 外交；
- 任务路线；
- 后续事件；
- 其他玩家可见结果

则应回滚整个季度。

## 16.4 回滚流程

回滚按照以下顺序进行：

1. 将季度状态改为“正在修正”；
2. 隐藏原结果；
3. 冻结下一季度行动；
4. 确认错误影响范围；
5. 恢复季度开始状态；
6. 重新执行受影响结算；
7. 重新完成全局审核；
8. 发布修正结果；
9. 保存原结果和修正原因。

---

# 第十七章 季度归档

## 17.1 归档内容

每个季度应保存：

- 季度开始状态；
- 玩家原始行动；
- 主持人整理内容；
- AI结构化方案；
- 正式行动单；
- 冲突组；
- 随机判定；
- 主持人修改记录；
- 最终结果；
- 公共日志；
- 私密报告；
- 异议与修正记录。

## 17.2 历史记录

历史记录应支持查询：

- 国家历史；
- 领土变化；
- 政策历史；
- 外交历史；
- 战争历史；
- 建设历史；
- 科技历史；
- 任务路线；
- 事件链；
- 情报记录；
- 主持人审计记录。

## 17.3 下一季度输入

系统根据本季度结果自动生成下一季度输入：

- 持续政策；
- 持续项目；
- 跨季度围城；
- 持续情报行动；
- 待处理事件；
- 到期效果；
- 新生效效果；
- 必须支付的维护；
- 玩家下季度提示。

# 第十八章 主持人季度检查清单

## 18.1 开始季度前

主持人确认：

- [ ] 上季度已经完成；
- [ ] 异议已经处理；
- [ ] 跨季度项目已经导入；
- [ ] 季节已经更新；
- [ ] 收入和维护已经结算；
- [ ] 建筑、政策和改革生效时间正确；
- [ ] 军队、地区和国库状态正确；
- [ ] 本季度事件候选已经生成。

## 18.2 行动截止前

主持人确认：

- [ ] 所有玩家已经看到本季度事件；
- [ ] 玩家可以提交所有行动类型；
- [ ] 秘密行动可见范围正确；
- [ ] 明显歧义已经要求补充；
- [ ] 截止时间已经通知所有玩家。

## 18.3 行动截止后

主持人确认：

- [ ] 所有行动已经锁定；
- [ ] 每个国家的行动清单已经生成；
- [ ] 行动主体没有明显重复；
- [ ] 建设和研究槽位没有明显冲突；
- [ ] 地区征募与补员没有冲突；
- [ ] 军事命令没有自相矛盾；
- [ ] 自定义行动已经初步整理；
- [ ] AI结构化方案已经审核；
- [ ] 需要玩家确认的内容已经确认。

## 18.4 正式结算时

主持人确认：

- [ ] 强制状态优先处理；
- [ ] 事件回应已经处理；
- [ ] 外交协议双方一致；
- [ ] 政策与改革已经生效；
- [ ] 情报与反间谍冲突已经处理；
- [ ] 建设进度正确；
- [ ] 研究分配正确；
- [ ] 征募、补员和人口扣除正确；
- [ ] 军队移动按照WEGO处理；
- [ ] 所有战斗已经结算；
- [ ] 围城和占领状态正确；
- [ ] 自定义行动已经处理；
- [ ] 季度末状态已经更新。

## 18.5 发布前

主持人确认：

- [ ] 国库和资源没有重复扣除；
- [ ] 人口数据正确；
- [ ] 军队位置唯一；
- [ ] 领土状态一致；
- [ ] 外交和战争状态一致；
- [ ] 信息隔离正确；
- [ ] AI叙事未创造额外事实；
- [ ] 各国报告已完成；
- [ ] 公共世界日志已完成；
- [ ] 所有结果已由主持人批准。

# 第十九章 首版简化原则

首版主持人结算应优先保证：

- 行动能够被理解；
- 结果能够被解释；
- 世界状态保持一致；
- 玩家秘密不被泄露；
- 主持人工作量可以承受。

首版不要求所有行动都使用精确概率和复杂公式。

对于尚未建立数值模型的内容，可以采用：

1. 主持人整理事实；
2. AI提出结果范围；
3. 系统执行基础随机；
4. 主持人确认最终结果；
5. 保存裁决依据。

不得因缺少专项公式而阻止玩家提出合理行动。

---

# 第二十章 核心流程摘要

每个季度的主持人工作可以概括为：

> 更新状态 → 生成事件 → 收集行动 → 锁定提交 → 整理行动 → AI结构化 → 处理冲突 → 按顺序结算 → 审核信息 → 集中发布 → 处理异议 → 归档季度。

主持人不需要亲自完成所有计算，但必须理解、审核并批准所有重要结果。
