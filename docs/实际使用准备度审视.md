# 实际使用准备度审视

日期：2026-10-19，更新包含当日整体复查。目标是让一组同学在不同地点，由一名主持人持续开展国家战略剧本。依据当前工作区源码、运行配置、既有浏览器验收和自动回归判断；旧设计文档中的计划功能不计为已实现。

## 判断

当前可以进行熟悉系统的人带领的小范围试玩。政策提交、讨论补充、审核、结算、统一发布和进入下季已经形成闭环，四个主要系统都有基础数据和结算入口。

存档恢复、新局管理、结算更正、长文本续写和账号管理均已补齐基础实现。正式开展持续多周的远程游戏前，仍需完善玩家结果摘要、指定国家的反馈交付与成员交接，配置正式远程运行环境，并准备能执行的简版剧本规则。本次整体复查发现并修复了权限、解除分配、失效登录、政策重试和代理限制的问题，详细边界见 [整体复查与剩余缺口](./整体复查与剩余缺口-20261019.md)。

当日另加入可选的结算速览与主持人反馈起草。速览按成员权限读取已发布文字及实际账目，支持简短、适中、详细三档篇幅；真实模型效果仍待配置密钥后验证，固定的本国完整变化展示也尚未补齐。它不替代下面的远程部署、规则准备和试玩验收。见 [模型辅助配置与使用](./模型辅助配置与使用.md)。

## 正式开局前优先处理

### 1. 存档备份和恢复

2026-10-17 已补齐手动/定时备份、发布前恢复点、定时保留策略、源码快照与校验，以及恢复到全新数据库的命令。已从当前试玩库恢复到独立数据库，对比 50 张表的内容摘要，并验证四个账号登录、历史结算和私聊权限。见 [备份恢复验收](./存档备份与恢复验收.md) 和 [维护说明](../infrastructure/database/BACKUP.md)。

当前启用了本地试玩自动备份。正式运行仍需把备份复制到独立设备或存储，安排失败通知、磁盘检查和定期恢复演练。数据库恢复是维护动作，恢复命令不会自动切换正在运行的服务。源码快照覆盖未提交和未追踪的项目代码；Git 整理和发布版本标记仍是后续部署工作。

验收：服务重启数据仍在；从备份恢复到独立环境后，世界、政策、私聊、历史反馈和权限一致。

### 2. 结束、归档与另开一局

2026-10-18 已补齐“本局管理 → 结束并归档 → 新建一局”的流程。历史游戏继续出现在列表，按原权限查看地图、政策、私聊和已发布结算；页面与数据库同时限制修改。结束说明、操作者、最后回合和时间有记录。已经在隔离副本中实际完成结束、另开一局、返回旧局查阅历史。原试玩局继续保留。见 [结束归档验收](./游戏结束与历史归档验收.md)。

继续保留一场活动游戏的限制。新局目前从空白国家配置开始，成员、地图、规则等正常重新准备；剧本导入导出和复制初始配置仍待后续开发。归档不会自动执行或公开未发布的结算。

验收：主持人通过页面结束试玩局，历史可查，再新建正式局；过程不需要改数据库状态或清库。

### 3. 发布更正与即时编辑边界

2026-10-18 已补齐“更正已发布结果”。支持公报全文、单份政策反馈、国库／人力增减、军队当前兵力；原发布快照保留，更正单独追加原因、操作者、前后值、时间和实际记账季。文字读取修正版；数值始终补正当前状态，不回写旧季余额或重跑旧经济。国家账目将补正单列，旧回合标注“已更正”，当前季可直接查看最近更正。

私人反馈、费用和兵力更正仅主持人与所属国家玩家可见，公开公报勘误全员可见。版本检查和请求标识防止旧窗口覆盖及网络重试重复扣款；更正后的余额会让未发布旧资源计划报冲突，需要重新核对。

地图初始布置保留；开局后的即时地块修改、创建城市／军队与直接移动，必须明确开启“即时更正”、填写原因并校验地图版本，地图记录留痕。普通移动、占领、兵力与征募继续通过结算统一发布。地图揭示仍沿用既有的即时交付／探索计划区分。已结束的游戏继续只读。详见 [结算更正验收](./结算更正与即时编辑验收.md)。

当前不提供历史整季回滚，不自动补算更正引发的外交、经济、探索等连锁效果。复杂错误由主持人分项追加补正；城市建设等尚无专用结算变化入口的内容仍需明确的手工地图处理。

验收：漏扣费用、兵力填错、反馈笔误能通过正常页面处理，原结果和更正原因可追溯；运行中的普通裁决不会误走即时编辑。

### 4. 长文字稿件在意外关闭后可恢复

2026-10-19 已补齐政策、消息和结算文字的本地续写。未创建的政策保留标题、全文、类别、保密设置和地图引用；现有政策保留未确认保存的改动。政策和结算恢复前检查版本与阶段，旧版本、旧回合、已提交／已发布内容只供复制。未发送消息在重新验证会话权限后恢复，发送请求标识一同保留，断线后重试不会换一个标识重复发送。

本地记录按账号、游戏、回合／对象隔离，服务器确认保存或发送成功后才清除；多页面同时写入时阻止旧页面覆盖本地新稿。存储失败明确提示复制文字，不冒充成功。见 [文字草稿续写验收](./文字草稿续写验收.md)。

结算的本地恢复仅覆盖公报与政策反馈文字，费用、征兵、战斗和地图等结构化计划仍需“保存草稿”存到服务器。当前副本只在本设备、同一浏览器和网址中恢复；更正表单、规则设置和主持人独立整理稿尚未接入本地恢复。清除浏览器站点数据会删除其本地稿。

验收：刷新、浏览器异常关闭、断网和会话过期后，能找回应保留的文字；保存失败不冒充已保存。

### 5. 实际远程运行和账号管理

已有 Docker/Nginx 部署骨架，生产模式会启用安全 Cookie。当前正在运行的是本机开发预览，尚未完成实际公网环境的部署与验收。

2026-10-19 已补齐账号改密、主持人协助一次性码重置、维护者恢复主持人账号、邀请注册和持久登录限速。重要操作重新验证当前密码，改密后撤销所有旧登录；协助按本局成员权限限制并保留记录。当前本地试玩已改为邀请码注册。见 [账号管理与登录保护](./账号管理与登录保护验收.md)。

远程运行仍需正式配置、HTTPS、稳定进程与启动恢复、迁移步骤、健康检查、日志与发布回退。数据库和缓存应只在所需网络内访问，替换开发示例凭据；反向代理还需核实客户端地址和限速效果。当前没有邮件／短信自动找回，熟人组可由主持人或维护者核实身份后协助。

验收：不同地点的真实设备能进入、提交、讨论和读取结果；服务重启后可继续；忘记密码有明确处理路径；发布版本和数据库迁移可追溯。

### 6. 正式剧本的最小规则与初始配置

目前“界河危机”的具体数值和战果是演练内容。正式剧本需先明确：

- 一季代表多久、何时截止、临时缺席怎样处理。
- 金钱和人力的单位、收入系数、征募与维护成本、建设的代价和生效时间。
- 一季军队能移动多少、何时交战、撤退和占领怎样处理、掷骰怎样影响裁决。
- 视野、侦察、地图交换和秘密行动怎样获取与失去信息。
- 同回合互相冲突的政策按什么顺序处理，玩家哪些信息属于确定事实或估计。
- 地图、省份、国家、资源、军队、政府及开场局势配置。

其余保持自由政策和主持人裁决。地图交换、秘密行动、复杂贸易和角色故事可以先通过政策、信息交付及文字反馈运行，待重复操作形成规律后再决定专门自动化。

## 内测时继续验证

1. 使用预计的玩家数、地图大小和政策量，让真实同学独立操作数回合，记录主持人每轮用时和重复录入，而非仅由开发者切换演示账号。
2. 包含冬季跨年、政策/条约到期、占领与割让、部队撤离后情报变旧、玩家补充、重复点击、断网重试和两窗口冲突。
3. 验证更长的政策、讨论历史和地图在目标设备上的表现。目前试玩地图只有 12 × 8，不能据此推断正式规模性能。
4. 继续完善按权限筛选的本国数值变化展示。可选模型速览现已覆盖反馈归纳和本回合实际收支；完整军队、领土、外交与政府变化仍需结合国家页、地图和反馈核对，不能直接把主持人的完整变化列表交给玩家。
5. 随剧本推进补事件与线索记录、指定多国共享反馈，以及常用裁决模板，降低主持人长期记忆和重复填写负担。

## 可以后置

完整 EU4 科技树、复杂贸易流向、自动补给、自动战斗胜负、海军、完整人物养成、AI 代写与自动裁决、多房间平台，以及更多地形和地图模式，都不是这次小范围国家战略内测的前提。当前四个主要系统可以继续采用已有基础加主持人裁决。

## 建议开发顺序

1. 固定当前版本，补备份、恢复和游戏结束/归档，建立正式局。
2. 补发布更正与即时编辑边界、稿件续写；同时整理简版规则和正式初始数据。
3. 完成远程部署与账号管理，进行真实多人连续试玩。
4. 根据实际每轮耗时继续优化主持人工作区和玩家结果摘要，再扩展高频玩法。
