# 后续迭代安排

记录日期：2026-10-29。实现前核对基线：`892c148`。本轮已完成下面三处文字保护，手机端重构与其他待办继续保留。

## 本轮已实现：三处文字保护

### 1. 主持人未提交的审核意见与政策解释

- 原问题：输入只保存在页面内存；刷新、关闭或重新打开页面后无法恢复，离开提醒也未覆盖这两类输入。已经提交的审核结果仍保存在服务器。
- 本轮实现：复用现有本地暂存机制，按账号、游戏、回合和政策区分草稿；显示暂存状态，将未提交审核文字纳入离开保护。暂存失败明确报错；另一页面更新过草稿时拒绝覆盖，保留本页文字供复制。
- 恢复边界：先核对当前主持人权限与政策版本；版本变化时保留查看、复制能力。保存某类审核结果后，仅清理对应的已提交草稿。
- 验收：刷新后可恢复；切换政策不串稿；未提交离开有提示；保存失败保留文字；恢复草稿不会自动批准、退回或发布政策。

### 2. 移除有内容的政策分项时提供保护

- 原问题：移除会立即更新编辑内容与本地暂存。尚未保存到服务器的新分项可能失去唯一副本。
- 本轮实现：提供可连续使用的“撤销移除”，保留被移除分项的内容与原顺序参考；撤销时插回当前内容，不覆盖删除后继续填写的其他分项。空白分项直接移除。
- 撤销边界：撤销记录随未保存的本地稿一起暂存，刷新后可恢复。明确保存到服务器或正式提交后结束本次撤销记录；界面提示这一边界。若服务器版本已变化，本地备份仍包含被移除内容，可查看、复制。
- 验收：误移除有内容分项可取消或恢复；正文、自拟标题、分类和地图引用完整；连续操作不覆盖其他新输入；移除草稿分项不会立即改写正式提交历史。

### 3. 新回合提供旧回合本地草稿入口

- 原问题：回合变化时重置当前编辑器，旧文字仍在本地存储，但整份政策页面没有旧回合草稿的查看入口。
- 本轮实现：发现同账号、同游戏、同作者与国家的旧回合草稿时提供入口。打开时逐份向服务器核对当前读取权限，通过后才展示所属回合和本地全文，允许复制；包含未撤销的移除记录。与当前回合的编辑稿分别处理，读取失败或无权限时不显示私有正文，也不删除原备份。
- 恢复边界：核对原政策的当前读取权限；禁止将旧回合内容静默覆盖到新回合或自动提交。
- 验收：留在编辑页等待主持人推进回合、随后刷新、以及已有新回合草稿等场景下，旧文字均能按权限查看、复制，且不污染新稿。
